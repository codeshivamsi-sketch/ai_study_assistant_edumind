      gRPC server
        grpc/server.ts: NotifyQuizReady, dynamic proto load, enqueues BullMQ job
      Identity
        identity.ts: requireUser, X-User-Id header, raw SQL against core-api's users table
      Async jobs
        queue.ts + jobs/notifyQuizReady.ts: BullMQ NotifyQuizReady queue and processor
      Persistence
        prisma/schema.prisma: Notification model only, no User model/relation

      Postgres :5432

      Redis :6379

## Database Schema

```mermaid
erDiagram
    USERS ||--o{ DOCUMENTS : owns
    DOCUMENTS ||--o{ QUIZZES : contains
    QUIZZES ||--o{ QUIZ_ATTEMPTS : "attempted via"
    USERS ||--o{ QUIZ_ATTEMPTS : attempts
    USERS ||--o{ NOTIFICATIONS : notifies

    USERS {
        uuid id PK
        string email UK
        string name
        timestamptz created_at
    }
    DOCUMENTS {
        uuid id PK
        uuid user_id FK
        string title
        string status
        timestamptz created_at
    }
    QUIZZES {
        uuid id PK
        uuid document_id FK
        string topic
        jsonb questions
        timestamptz created_at
    }
    QUIZ_ATTEMPTS {
        uuid id PK
        uuid quiz_id FK
        uuid user_id FK
        jsonb answers
        numeric score
        timestamptz created_at
    }
    NOTIFICATIONS {
        uuid id PK
        uuid user_id FK
        uuid quiz_id
        text message
        boolean read
        timestamp created_at
    }
```

## Delete Behavior

```mermaid
flowchart TD
    USERS[(users)]
    DOCUMENTS[(documents)]
    QUIZZES[(quizzes)]
    QUIZ_ATTEMPTS[(quiz_attempts)]
    NOTIFICATIONS[(notifications)]

    USERS -->|CASCADE| DOCUMENTS
    DOCUMENTS -->|CASCADE| QUIZZES
    QUIZZES -.->|"RESTRICT ⛔"| QUIZ_ATTEMPTS
    USERS -.->|"RESTRICT ⛔"| QUIZ_ATTEMPTS
    USERS -->|CASCADE| NOTIFICATIONS
```

Legend: solid `CASCADE` — deleting the parent row deletes its children too. Dashed `RESTRICT ⛔` — deleting the parent is blocked at the DB level while child rows exist.

## Request Flow

```mermaid
sequenceDiagram
    participant C as Client
    participant R as core-api routes.create_quiz
    participant I as core-api identity.get_current_user
    participant O as core-api routes._get_owned_document
    participant DB as Postgres (edumind)
    participant G as core-api grpc_client.notify_quiz_ready
    participant NS as notifications grpc/server.notifyQuizReady
    participant Q as notifications queue (BullMQ)
    participant W as notifications jobs.processNotifyQuizReady

    C->>R: POST /quizzes {document_id, topic, questions}
    R->>I: Depends(get_current_user)
    I->>DB: SELECT * FROM users WHERE id = X-User-Id
    DB-->>I: user row (or 401 if missing/unknown)
    I-->>R: user
    R->>O: _get_owned_document(document_id, user, db)
    O->>DB: SELECT documents WHERE id = ? AND user_id = ?
    DB-->>O: document row (or 404 if not found/not owned)
    O-->>R: document
    R->>DB: INSERT INTO quizzes (...)
    R->>DB: COMMIT
    DB-->>R: quiz row (refreshed)
    R->>G: await asyncio.to_thread(notify_quiz_ready, user.id, quiz.id)
    G->>NS: gRPC NotifyQuizReady(user_id, quiz_id)
    NS->>Q: enqueueNotifyQuizReady({user_id, quiz_id, message})
    Q-->>NS: job accepted
    NS-->>G: {accepted: true} (or RpcError, caught, logged, quiz creation still succeeds)
    G-->>R: (return, or swallowed RpcError)
    R-->>C: 200 {quiz}
    Q->>W: process job (async, after response already sent)
    W->>DB: INSERT INTO notifications (user_id, quiz_id, message)
```
